SQLPub 正式上线独立的**系统状态页**（[status.sqlpub.com](https://status.sqlpub.com)），公开各核心服务的运行状况。控制台顶部也会实时显示整体状态，方便你在使用产品前快速确认平台是否健康。

## 为什么需要状态页

数据库是业务的核心依赖。当控制台、API 或 Web SQL 客户端出现异常时，用户往往难以判断是自身配置问题，还是平台侧故障。

状态页的目标是：

- **透明**：公开各组件当前状态，减少信息不对称
- **可追溯**：保留事件时间线与近 30 天历史记录
- **可触达**：控制台内一键跳转，无需单独收藏地址

## 监控哪些组件

状态页覆盖 SQLPub 核心服务链路上的关键组件：

| 组件 | 说明 | 监控区域 |
| --- | --- | --- |
| 数据库连接 | 通过 TCP/MySQL 协议连接活跃数据库 | 中国、新加坡 |
| 共享实例操作 | 免费版 / 开发版实例的创建与管理 | 中国、新加坡 |
| Serverless 实例操作 | 独享实例的创建、伸缩与管理 | 中国、新加坡 |
| 控制台 API | 管理控制台的后端接口 | 全球、中国、新加坡 |
| 控制台前端 | 控制台网页界面加载与使用 | 全球、中国、新加坡 |
| 账号注册 | 新用户注册与验证邮件 | 全球、中国、新加坡 |
| 控制台登录 | 邮箱密码登录 | 全球、中国、新加坡 |
| 官网 | sqlpub.com 及公开页面 | 全球 |

此外，底层 **Cluster Autoscaler**（Serverless 弹性伸缩）也在探测范围内，确保计算资源调度健康。

## 四种服务状态

与主流云厂商状态页一致，SQLPub 使用四级状态标识：

| 状态 | 含义 |
| --- | --- |
| 运行正常 | 服务完全可用 |
| 性能下降 | 部分功能受影响，但核心服务仍可用 |
| 服务中断 | 服务不可用 |
| 维护中 | 计划内维护 |

整体状态取所有组件与进行中事件的**最差等级**，一目了然。

## 状态页功能

访问 [status.sqlpub.com](https://status.sqlpub.com) 可查看：

- **整体状态横幅**：当前平台是否正常运行
- **组件列表**：各组件按区域展示状态
- **30 天可用性条**：鼠标悬停可查看每日状态
- **进行中事件**：未恢复故障的实时进展
- **历史记录**：近 30 天已解决事件与时间线

每条事件包含「调查中 → 监控中 → 已解决」的进展更新，便于回顾故障处理过程。

## 控制台状态徽章

控制台（console-ui v0.6.0）顶部导航新增**状态徽章**：

- 每 60 秒自动拉取 `status.sqlpub.com` 的 badge 接口
- 显示「所有系统运行正常」或对应异常状态
- 点击即可在新标签页打开完整状态页

登录控制台时，无需离开当前页面即可感知平台健康状况。

## 技术架构

状态页由独立项目 **sqlpub-status** 提供，与主业务服务解耦部署：

```
定时探测（HTTP / MySQL）
    ↓
聚合组件 & 区域状态
    ↓
写入 MySQL（probe_results、incidents…）
    ↓
API（/api/v1/status、/api/v1/status/badge）
    ↓
status.sqlpub.com 前端 + 控制台 StatusBadge
```

探测支持两种类型：

- **HTTP 探测**：控制台、官网、API、Web SQL 客户端等
- **MySQL 探测**：验证数据库 TCP 连通性与协议可用性

当探测持续失败时，系统可**自动创建事件**并记录时间线，运维人员也可手动发布维护公告。

## 区域化监控

SQLPub 在中国与新加坡均部署有资源节点。状态页按 **全球 / 中国 / 新加坡** 分区展示，某一区域异常不会影响其他区域的状态判断。

例如，2026 年 7 月 1 日中国区域曾出现实例操作性能下降，状态页记录了完整的事件调查与恢复过程；新加坡区域同期保持正常运行。

## 如何使用

1. 直接访问 [status.sqlpub.com](https://status.sqlpub.com)
2. 或在 [控制台](https://console.sqlpub.com) 顶部点击状态徽章
3. 连接数据库遇到异常时，先查看状态页确认是否为平台侧故障
4. 订阅后续可增加的通知渠道（邮件 / Webhook，规划中）

## 小结

系统状态页的上线，是 SQLPub 在可用性与透明度上迈出的重要一步。我们将持续完善探测覆盖与事件响应流程，让你在使用 Serverless MySQL 时更加安心。

如有故障反馈，仍可通过控制台 **问题留言** 联系我们；状态页将作为官方故障信息的权威来源。
